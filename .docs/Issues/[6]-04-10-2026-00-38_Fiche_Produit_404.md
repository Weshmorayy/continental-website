# Issue : La fiche produit renvoie 404

## Détails
- **Date** : 05-10-2026-00-38
- **Statut** : Résolue

## Description

Un produit créé depuis le portail était listé au catalogue, et le clic sur sa
tuile ouvrait une 404. Tous les produits ajoutés de cette manière avaient une
page de détail morte, alors que leur nom, leur prix et leur image
fonctionnaient parfaitement dans la liste.

## Cause Racine

`getSiteProduct()` dans `src/lib/atelier.ts` ne consultait que l'API admin
multi-clients — `fetchAdminContent()`, qui renvoie `null` quand
`ATELIER_ADMIN_URL` est vide — et le fichier `src/data/products.ts` écrit en
dur dans le dépôt. Elle n'interrogeait jamais Supabase, alors que
`getSiteProducts()`, utilisée pour la liste, le faisait. Les six produits
d'origine fonctionnaient uniquement parce qu'ils sont aussi écrits dans les
fichiers du dépôt.

La divergence ne pouvait pas être vue sans créer un produit : un produit
présent dans les deux sources aurait produit le même résultat par les deux
chemins. Seule une donnée réellement absente du dépôt — donc issue de
Supabase — exposait l'écart.

## Solution

`getSiteProduct()` passe maintenant par `getSiteProducts()` et utilise donc
exactement la même résolution à trois canaux que la liste. Vérifié :
`/produit/test` renvoie 200 avec son image, et les six pages produits
d'origine renvoient toujours 200.

## Prévention

Toute fonction qui résout un élément doit utiliser la même résolution de
canaux que celle qui les liste. Deux résolveurs différents pour un même jeu de
données dériveront toujours : il suffit qu'un canal change d'ordre.
